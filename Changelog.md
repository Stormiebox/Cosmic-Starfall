## [v2.0.16]

### 🔗 Cross-Mod Integration
- [Integration] **Starfall's Shop-Eligible Systems Registered With Cosmic Vault's New Upgrade Category API (`lib/upgradegenerator.lua`):** Registers all 6 of Starfall's shop-generatable systems into Cosmic Vault's new `cosmicvaultupgradecategories.lua` (v3.7.0): `subspaceCargo.lua` → Civilian, `repairDrones.lua` → Military, `bastionSystem.lua` → Military, `macrofieldProjector.lua` → Military, `pulseTractorBeamGenerator.lua` → Misc, `XperimentalHypergenerator.lua` → Misc. ## [v2.0.15] - Emergency Hotfix

### 🪲 Bug Fixes
- [Bugfix] **Set Bonus Recalculation Wiped Every Installed Subsystem's Own Passive Bonuses (starfall_setbonuses.lua):** `recalculateBonuses()` (fires on every turret add/remove/destroy and on every sector reload or server restart) called `entity:removeScriptBonuses()` before reapplying its own doctrine/set-bonus deltas. That call clears every script-added bonus on the entity, not just this script's own — so it was also wiping each individually-installed subsystem's own base passive bonuses (Bastion System's shields, Overpowered Core's energy, etc.), which are applied once at their own install and never reapplied by this file. Since this runs on nearly any loadout change, a ship's subsystem bonuses could vanish the moment a turret was added or removed. Now tracks its own set-bonus keys and removes only those via the scoped `entity:removeBonus(key)`.
- [Bugfix] **Veil's Fire Rate Penalty Computed a Negative Multiplier (bastionSystem.lua):** `CosmicVaultBuffs.applyBuff`'s multiplier is a scale factor (`1.0` = unchanged), not a raw delta. Veil's "-25% FireRate" passed `-VeilFireRate * 0.01` (`-0.25`) directly, which computed a nonsensical negative FireRate multiplier instead of the intended -25%. Fixed to `1.0 - VeilFireRate * 0.01`.
- [Bugfix] **Multiphase's Shield Recharge Reset Used a Broken Formula (bastionSystem.lua):** Multiphase tries to make shields recharge instantly after a hit while active. It computed this by negating the ship's current recharge delay and passing that as the buff multiplier, which (same scale-factor-vs-delta issue as above) produced a negative multiplier instead of reliably zeroing the stat out. Replaced with a direct scale factor of `0`.
- [Bugfix] **Quantum's Fire Rate Penalty Had the Same Negative-Multiplier Bug (XperimentalHypergenerator.lua):** Same fix as Veil's above, applied to the Quantum Field's "-60% FireRate" penalty: `1.0 - QuantumFirerateSlow / 100`.
- [Bugfix] **Focused Jump Granted Roughly 60,000% Hyperspace Range Instead of +120% (XperimentalHypergenerator.lua):** The buff call passed `FocusedBonusRange`, an absolute range quantity (also used elsewhere by the cooldown formula), directly as the scale factor. Since that value is typically in the hundreds, the resulting multiplier was enormous. Fixed the buff call to pass the correct scale factor (`1.0 + FocusedIncrease / 100`) without touching `FocusedBonusRange` itself, which the cooldown formula still needs unchanged.

## [v2.0.14] - Full Workspace Bugfix & Optimization Sweep

A full line-by-line pass over all 70 `.lua` files in `data/scripts/`, per this workspace's standing `ReviewCode` protocol. No new features and no breaking API changes to dependent mods; patch-version bump only.

### 🪲 Bug Fixes

- [Bugfixed] **Megacomplex Configuration Silently Lost on Every Restart (`complexCraft/complexCore.lua`, `MX.restore()`/`MX.restoreOperate()`):** `MX.restore(values)` never read its own `values` parameter. It instead did `local restoredValue = secureTable` — `local` shadowed the module-scope `restoredValue` that `MX.restoreOperate()` actually reads, confining the assignment to `MX.restore()`'s own function body, and `secureTable` itself is a name that only exists as a `local` inside the unrelated `MX.secure()` function, so outside of it the read resolved to an unset global (always `nil`) regardless of the shadowing. `MX.restoreOperate()` then read `restored[1]`/`restored[2]`/`restored[3]` — `restored` (no "Value") is a different, never-declared global, which would throw `attempt to index a nil value` the moment `restoredValue` was ever actually non-nil — and compared `isCons`/`isStor` (tables) directly against a number with `<` with no `#`, which throws `attempt to compare table with number`. Net effect: every Megacomplex's production/consumption/storage configuration was silently and completely discarded on every server restart or sector reload, and the two latent crash bugs in the same code path would have fired the moment the primary shadowing bug was naively patched without also fixing them. All three defects fixed together: `MX.restore()` now assigns `restoredValue = values.secureTable` (no `local`, so it updates the actual module-scope variable), and `MX.restoreOperate()` now reads `restoredValue[1..3]` with `#` on all three length checks.
- [Bugfixed] **Unrestricted Cargo-Destruction RPC (`complexCraft/complexCore.lua`, `MX.ServerDebugPurge`):** Registered via `callable(MX, 'ServerDebugPurge')` with no ownership check of any kind. Its only intended caller, `MX.DebugPurge()`, is gated behind `if _debug then` (a compile-time `false`), but `callable()` registration doesn't care how a function is reached — any connected player could call `invokeServerFunction('ServerDebugPurge')` directly against any Megacomplex core they can reference and wipe all Energy Cell cargo from it and from every entity docked to it, with no permission check, cost, or cooldown. Added the same owner/alliance-only guard already used by `overpoweredCore.lua`'s `ApplyDebug()`/`ApplyOCC()`.
- [Bugfixed] **Unrestricted Damage RPC (`systems/bastionSystem.lua` and `systems/macrofieldProjector.lua`, `DamageTarget`):** Both files defined an identical `DamageTarget()` function explicitly commented `--for debug`, registered via `callable(nil, "DamageTarget")` with no ownership check and, unlike this file's other debug helpers, no `if _debug then` guard around its body either. Any connected player could call `invokeServerFunction("DamageTarget")` directly and deal -100000 durability / -400000 shield (bastionSystem.lua) or -400000 shield (macrofieldProjector.lua) to whatever the target ship's `selectedObject` was, for free, with no cooldown. Added the same owner/alliance-only guard used by `overpoweredCore.lua`'s debug RPCs to both copies.
- [Bugfixed] **`entity/mainCaliber.lua` Crashed Every Dedicated Server on Every Ship Load:** `locLines['overload'] = "..." %_t` sat at unguarded module top-level scope. This script is `addScriptOnce`'d onto every player/alliance ship and station from `entity/init.lua`, so the server evaluates the file's top-level statements too, and `%_t` at true global scope crashes a dedicated server on startup (same bug class documented and fixed in v2.0.13, but this specific file was missed in that pass). Wrapped the assignment in `if onClient() then` — `locLines['overload']` is only ever read from `mainCaliber.visuals()`, which already starts with `if onServer() then return end`, so nothing server-side needed it.
- [Bugfixed] **`lib/tooltipmaker.lua` Crashed the Server on Every Subsystem-Item Load:** Same bug class as above — `locLines[...] = "..."%_t` at unguarded module scope — reached server-side via unconditional top-level `include("tooltipmaker")` in four separate "systems" item scripts (`overpoweredCore.lua`, `repairDrones.lua`, `pulseTractorBeamGenerator.lua`, `macrofieldProjector.lua`). Wrapped in `if onClient() then`; `locLines` is only read inside `makeTurretTooltip()`, which builds client-rendered tooltip text.
- [Bugfixed] **`complexCraft/mainCaliber.lua` Had the Same `%_t` Bug (Dead File):** Same fix applied for consistency, though this file currently has no `addScriptOnce`/`include` site anywhere in the mod — `entity/mainCaliber.lua` is the version actually attached to ships. Left in place rather than deleted; flagged below.
- [Bugfixed] **`OCore.aquaSave()` Threw a Lua Error on Every Press (`complexCraft/OCnode.lua`):** Called `Aquaflow.createNewFileC('AquaTest', 'Meow!')`, a function that never existed on the neutralized `Aquaflow` security-patch stub (see `lib/Aquaflow.lua`) — every click of the "Save" button in the Experimental Features debug panel threw `attempt to call a nil value`. Routed through `Aquaflow.saveData(...)`, the same safe stub call the sibling `OCore.tryNewFile()` already uses.
- [Bugfixed] **`OCore.inventoryCheck()` Crashed on an Empty Inventory Slot (`complexCraft/OCnode.lua`):** `turret:getWeapons()` was called unconditionally after an `if turret then ... end` guard block rather than inside it. `Player():getInventory():find(14)` returns `nil` whenever nothing occupies that slot, and the unguarded call then threw `attempt to index a nil value (local 'turret')`. Restructured so the whole weapon-inspection block runs only when `turret` is non-nil.
- [Bugfixed] **Color-Picker Textboxes Swapped (`complexCraft/OCnode.lua`, `OCore.initUI()`):** The Saturation textbox was wired to `colorChangeV` and the Value textbox to `colorChangeS`, so typing in one changed the other. Corrected the callback names to match each textbox's own letter.
- [Bugfixed] **`checkDoubleCast()` Misused `Player()` (`systems/raycast.lua`):** Called `Player(_sourceID)`/`Player(_targetID)` where `_sourceID`/`_targetID` are entity Uuids — `Player()` only ever accepts a player *index* everywhere else it's used in this codebase (`Player(callingPlayer)`, `Player(playerIndex)`). Passing an entity Uuid returns an invalid Player object whose `.name` is `nil`, so `nil == nil` always evaluated `true` regardless of actual ownership, defeating the same-owner check this function exists to perform. This function runs client-side inside `LaserOperate()`, a hot per-tick path (up to 100x/second while a beam is active) for every complex-craft main-caliber and macrofield-projector-style laser/beam effect. Replaced with `Owner(source).name == Owner(target).name`, which resolves ownership correctly from the already-fetched Entity objects.
- [Bugfixed] **Six Turret-Loadout Doctrine Set Bonuses Never Triggered (`entity/starfall_setbonuses.lua`, `recalculateBonuses()`):** Read `weapons[1].weaponType` and `weapons[1].weaponCategory`, neither of which exists on a `Weapon` object (confirmed against `Avorion Stubs/Weapon.lua` — both silently returned `nil`). This meant `turretCount.miner/.salvager/.pdc/.artillery/.laser/.launcher` never incremented, so the Mining, Salvage, Point Defense, Artillery, Energy, and Launcher Doctrine set bonuses (lines checking `turretCount.X >= 5`) could never activate on any ship, no matter its loadout. Fixed to use `WeaponTypes.getTypeOfItem(weapons[1])`, the established vanilla API for resolving an item's `WeaponType` (see `lib/inventoryitemprice.lua`'s own use of it) — added `include("weapontypeutility")` to reach it. Also removed the unused `wCat` local and a `previouslyActiveSets` local that was computed and never read.
- [Bugfixed] **`InterruptAura()` Missing `return` (`player/ui/auraCore.lua`):** Its server branch (`if onServer() then invokeClientFunction(...) end`) was missing the `return` present in the sibling `ApplyAura()`, so the server-side script instance fell through into a loop over its own permanently-empty `activeAuras` table (that table is only ever populated client-side) on every call. Added the missing `return`.
- [Bugfixed] **`combatGroup.remoteInvite()` Used the Wrong Player Reference (`player/ui/combatGroup.lua`):** Used `Player(callingPlayer)` inside a function reached via `invokeFactionFunction(targetID, ...)` from a different player's script instance — `callingPlayer` isn't meaningfully set by that dispatch path (it's not a client `invokeServerFunction` call), so this could resolve to the wrong player or `nil`. Changed to bare `Player()`, matching the confirmed-correct pattern used by `lib/Tech.lua`'s `callTechAuraSelf()`/`callTechAuraTarget()` for the exact same `invokeFactionFunction` → player-attached-script dispatch shape (see `auraCore.ApplyAura()`/`InterruptAura()`, which both already use bare `Player()` here).
- [Bugfixed] **Debug-Log Typo Silently Dropped Text (`lib/Neltharaku.lua` and `complexCraft/complexCore.lua`, `TSRbase()`/`MX.TSRbase()`):** Both files' else-branch assigned to a global `text` (typo for `_text`), so the intended `'non-table|'` suffix never reached the log line beneath it. Fixed both.
- [Bugfixed] **Dangling RPC Registration (`systems/pulseTractorBeamGenerator.lua`):** `callable(nil, "onInstallCheck")` registered an RPC target for `onInstallCheck`, whose body was commented out and never implemented or invoked anywhere in the file. Removed the dead registration.
- [Bugfixed] **`scaleSolar()` Never Wired Up (`lib/turretgenerator.lua`, `TurretGenerator.generateSOLARTORPEDOTurret`):** `TurretGenerator.scaleSolar()` — a dedicated function whose own header comment says it "assigns the solar torpedo the coaxial property always" — was defined but never called anywhere; `generateSOLARTORPEDOTurret` called the generic `TurretGenerator.scale()` instead. No current behavior change (SOLARTORPEDO's scale bands never reach the 5-slot coaxial threshold either way), but this wires up the function that was actually written for this weapon and removes a dead-code function. Left as a normal defect fix, not a design change, since the observable output is unaffected today.
- [Bugfixed] **Short `addScriptOnce` Paths (`systems/overpoweredCore.lua`, `ApplyDebug()`/`ApplyOCC()`):** Used `addScriptOnce("lib/entitydbg.lua")` and `addScriptOnce("complexCraft/OCnode.lua")` instead of the full `data/scripts/...` form used with zero exceptions everywhere else in this codebase (short-path resolution isn't reliably predictable from target type alone — see `Avorion_Modding_Codex.md`). Converted both to full paths.

### ⚡ Optimization

- [Optimization] **Dead Per-Second Computation on Every Ship in the Game (`entity/entityAlerts.lua`, `eA.update()`):** Ran a bare `Player()`/`Entity()` comparison every second, on every player/alliance ship and station in the game (this script is `addScriptOnce`'d mod-wide from `entity/init.lua`), computing a local `_opByPlayer` that nothing in this file — or anywhere else in the mod — ever read back. Removed the dead computation; the function's only real job, the one-shot `initSystem()` call, is untouched.
- [Optimization] **Cooldown Bypass via Sector Reload (`systems/bastionSystem.lua`):** Unlike its `systems/` siblings (`repairDrones.lua`, `XperimentalHypergenerator.lua`), this file had no `secure()`/`restore()` pair at all, so every cooldown and active-phase timer (`VeilIsReady`, `RecupIsWorking`, `MultiphaseIsReady`, `PulsarIsReady`, and their related state) reset to its default the instant the ship's sector unloaded and reloaded, or the server restarted — letting a player bypass any of the Bastion System's four ability cooldowns just by leaving and re-entering the sector. Added a `secure()`/`restore()` pair mirroring the exact shape already used by this system family. While auditing this file's state variables for the fix, found `VeilRefrFX`/`RecupBoxFX`/`MultiphaseRefrFX`/`PulsarLaserFX` were declared but never read or assigned anywhere else in the file — removed as dead locals (this system's visual feedback runs entirely through `updateStatusEffects()`'s `addShipProblem`/`removeShipProblem` calls, not through any live FX handle).
- [Optimization] **Cooldown Bypass via Sector Reload, Re-Validated (`systems/macrofieldProjector.lua`, `systems/pulseTractorBeamGenerator.lua`):** Same missing-`secure()`/`restore()` gap as `bastionSystem.lua` above, initially left unfixed pending a design pass on the risk noted below — re-validated and fixed. `pulseTractorBeamGenerator.lua`'s state (`GeneratorIsReady`/`GeneratorIsWorking`/`GeneratorAllowedPulses`) is entirely self-contained (no cross-ship target or FX), so it got the same full-state `secure()`/`restore()` pair as `bastionSystem.lua`. `macrofieldProjector.lua` is genuinely different from every other file in this system family: three of its four abilities (Renovating Ray, Shield Booster, Shield Synchronizer) lock onto another ship via a live `Entity` reference (`RenovatingRayTarget`/`ShieldBoosterTarget`/`ShieldSynchronizerTarget`) plus a cross-ship laser FX drawn through `raycast.lua` on *both* entities — state that cannot be safely resurrected after a reload, since the target's own `raycast.lua` instance resets too. Its `secure()`/`restore()` pair persists only the four cooldown timers (`RepairWaveIsReady`/`RenovatingRayIsReady`/`ShieldBoosterIsReady`/`ShieldSynchronizerIsReady`) and `_rarity`, closing the actual cooldown-bypass exploit, while deliberately leaving active-phase/target/FX state to reset to idle on restore — the correct behavior here, not a gap, since there is no live FX or target to resume regardless.

### 🔎 Reviewed, Not Fixed (flagged for a design decision)

- **`lib/Stations.lua`'s `_buildStationText()` wraps its `%_t` calls in a function that is then called unconditionally at module load** (`_buildStationText()` on the line right after its definition), rather than gating with `if onClient() then` like every other fix in this pass and in v2.0.13. A prior session's own comment in this file explains why: `stationNames`/`stationDesc` are read by `entity/stationfounder.lua`'s own unconditional top-level factory table on both server and client, so simply skipping the assignment server-side (the standard fix) would leave the Megacomplex's build-menu name and tooltip blank server-side. Whether merely being inside a function call — as opposed to genuinely deferring past the "initial script evaluation phase" `Avorion_Modding_Codex.md` describes — is actually sufficient protection could not be conclusively verified without live dedicated-server testing, and changing it to the standard pattern would introduce a confirmed regression in exchange for an unconfirmed fix. Left as-is.
- **`lib/turretingredients.lua` (and related files) rebalance several *vanilla* weapon types' crafting ingredients** (`WeaponType.ChainGun`, `RailGun`, `RocketLauncher`, `Laser`, `PulseCannon`), not just Starfall's own new weapons — e.g. ChainGun's values differ from vanilla's own (`investFactor` 0.4 vs vanilla's 0.3 on the Servo ingredient, `investable` 12 vs 10 on Ammunition S) and add an extra "High Pressure Tube" ingredient vanilla's ChainGun recipe doesn't have. This is pre-existing, intentional-looking, internally-consistent design, not a defect — noting it here only because it's more invasive than "purely additive" and the sweep surfaced it.
- **`complexCraft/complexCore.lua`'s `MX.SyncMainTables` accepts and stores `tableProduction`/`tableConsumption`/`tableStorage` from the client with no server-side validation.** No direct resource-transfer call (`pay`/`addGood`/`removeCargo` etc.) in this file consumes those three tables directly — the actual cargo movement goes through the separately-guarded `MX.ServerSendResourses` (which already restricts transfers to the complex and its own docked entities via a prior "Security Patch") — suggesting the synced tables are primarily client-display state. Tracing every individual station factory script this data eventually reaches was outside this pass's budget; noting it as worth a closer look rather than treating it as confirmed safe or confirmed exploitable.

## [v2.0.13] - Dedicated Server Crash: Unguarded Translation at Global Scope

### 🪲 Bug Fixes

- [Bugfixed] **Dedicated Server Crash on Player Login (`alertCore.lua`, `auraCore.lua`, `combatGroup.lua`):** All three are attached to every player via `Player():addScriptOnce(...)` from server-side code in `player/init.lua`, and all three built a `locLines` table of UI text using `%_t` directly at module top-level (true global scope, not inside any function or `if onClient()` guard). The server evaluates a script's top-level statements immediately as the file loads - including files it just attached to a player - and the server's Lua state never binds the UI localization metatable those operators dispatch through, so this crashed the server the instant any of the three files loaded for a connecting player. Fixed by wrapping each file's `locLines` population in `if onClient() then ... end` - the table is never needed server-side (it only feeds client-only alert/HUD UI), so skipping it entirely on the server is safe and changes no client-visible behavior.
- [Bugfixed] **Dedicated Server Crash on Megacomplex Station Placement (`complexCraft/complexCore.lua`):** Same root cause and same fix as above, but attached via an entity factory `scripts = {{script = "..."}}` entry (`entity/stationfounder.lua`) rather than `addScriptOnce` - the server crashed the moment a Megacomplex station was placed, since that's when the entity (and its attached scripts) actually gets created server-side.
- [Bugfixed] **`Stations.lua`'s Station Name/Description Table Had the Same Unguarded Global-Scope Crash, But Needed a Different Fix:** Unlike the UI-only files above, `stationNames`/`stationDesc` are read from `entity/stationfounder.lua`'s own top-level factory table (`name = getStationName('mx')`), which both the server and client evaluate - so the values are needed on both sides, and `if onClient()` would have silently broken the server-side factory listing. Moved the table's construction into a function (`_buildStationText()`), called once immediately - `%_t`/`%_T` is safe inside a function body regardless of when it's called, only true top-level module code is dangerous (see `Avorion_Modding_Codex.md`'s "UI Development" section for the full mechanism).

## v2.0.0

### ✨ New Features & 📦 Content Additions
- [Feature] **UI Integration:** The massive array of Starfall lore (Weapons, Stations, etc.) has been updated and structured natively.
- [Feature] **Subsystem Set Bonuses (Synergies):** Equip specific combinations of Starfall subsystems to unlock hidden buffs!
  - *The Aegis Matrix* (Bastion System + Overpowered Core): +20% Shield Recharge Rate and +10% Shield Durability.
  - *The Drone-Weaver Network* (Repair Drones + Pulse Tractor Beam): +25% Hull Repair Speed and +2 Max Fighters.
  - *The Void-Runner Configuration* (Xperimental Hypergenerator + Subspace Cargo): +20% Hyperspace Jump Range and +15% Velocity.
- [Feature] **Turret Set Bonuses (Fleet Doctrines):** Specialize your ship by equipping 5 or more of the same turret type (Vanilla or Modded) to unlock powerful Fleet Doctrines!
  - *Mining Doctrine* (5+ Miners): +15% Energy Generation, +15% Cargo Capacity.
  - *Salvage Doctrine* (5+ Salvagers): +20% Shield Durability.
  - *Point Defense Doctrine* (5+ PDCs/Anti-Fighter): +15% Fighter Dodge, +10% Velocity.
  - *Artillery Doctrine* (5+ Cannons/Mortars/Railguns): +15% Damage, +10% Velocity.
  - *Laser/Plasma Doctrine* (5+ Lasers/Plasma): +15% Damage, +15% Shield Recharge Rate.
  - *Launcher Doctrine* (5+ Launchers/Bolters): +20% Fire Rate.
- [Feature] **Active Set Bonus UI:** Radically redesigned the HUD element that dynamically displays your currently active Set Bonuses and Doctrines. It now flawlessly uses the native `addShipProblem` API alongside Cosmic Vault textures to render beautiful, non-obstructive visual indicators instead of manual text rectangles!
- [Feature] **Legendary Vault DoTs:** Integrated the new `CosmicVaultCombat` DoT framework into Legendary weapon generation.
- [Feature] **Dynamic Economy Hooks:** Megacomplexes are now fully integrated into `CosmicVaultEconomy`. If a Megacomplex over-accumulates resources beyond its configured limits and is forced to dump cargo into space, it now triggers a sector-wide **Market Crash** event!

### ⚙️ Changed & ⚖️ Balanced
- [Changed] **Native Cosmic Vault Integration:** Cosmic Starfall has been officially integrated into the Cosmic Series ecosystem. It now natively requires `Cosmic Vault` to run. Completely removed the obsolete `cosmicstarfalllib` bridge.
- [Changed] **Cinematic UI & QoL Overhaul:** Active systems now use `CosmicVaultUI.ShowCinematicBanner` for stunning on-screen feedback. Custom UI tabs now utilize proportional splitters for perfect scaling.
- [Changed] **Architecture Restructure & API Compliance:** Renamed all experimental `V2` scripts back to their canonical names, eradicated legacy UI scripts, and updated 70+ internal pathways to ensure global API compliance.
- [Changed] **In-Game Wiki Updates:** Updated the in-game wiki with relevant changes done to systems, turrets, and set bonuses. Updated weapon tooltips and stats to reflect current overhaul changes.
- [Balanced] **Core Subsystem Rebalance:** Overpowered Core stripped of broken hardcoded values, now utilizing true dynamic rarity scaling (+5% up to +15% energy stats).
- [Balanced] **Vanilla Power Creep:** Nerfed the flat exponential global damage multipliers applied to vanilla Chainguns (1.25x -> 1.10x) and Bolters (1.15x -> 1.05x) to restore late-game TTK balance.
- [Balanced] **Global Weapon Balance Pass:** Normalized all custom Starfall weapon DPS multipliers (previously up to 2.3x) down to +15-25% over vanilla to eliminate power creep. Rebalanced the MANTIS rockets to reduce visual spam and normalize damage output.

### 🐛 Bug Fixes & 🛠️ Optimization
- [Optimized] **English Translation & Localization:** Translated all Russian UI labels, tooltips, logs, and variables into English. Wrote a Python script to aggressively purge redundant/orphaned translations, reducing memory footprint.
- [Optimized] **Zero-Overhead Subsystem Synergies:** Completely eradicated the massive 1.0-second background polling loop in `starfall_setbonuses.lua`. Subsystem synergies and Fleet Doctrines are now fully event-driven, relying exclusively on native `onTurretAdded`, `onTurretRemoved`, and `onInstalledUpgradesChanged` hooks to yield mathematically zero TPS overhead during combat.
- [Optimized] **Asynchronous Performance Processing:** High-intensity iterative loops (like Repair Waves and Tractor Pulses) have been rewritten to execute asynchronously via `CosmicVaultTask.RunAsync()`, completely eliminating TPS drops during massive fleet battles.
- [Optimized] **UI Memory Leaks Sealed:** Injected `onRemove()` functions into UI scripts like the Combat Group and Active System interfaces. Previously, jumping sectors caused the UI to secretly stack invisible event listeners, leading to massive memory bloat in late-game.
- [Optimized] **PCall Wrapper Purge:** Swept core system scripts (`repairDrones.lua`, `subscapeCargo.lua`, `XperimentalHypergenerator.lua`) and all item generators (`weapongenerator.lua`, `turretgenerator.lua`, etc.) to remove unneeded and dangerous `pcall` wrappers, restoring natural stack trace logging and resolving logical errors.
- [Bugfixed] **Bastion System Math Fix:** Fully reversed the faulty mathematical logic. The system now natively scales positively (+69% up to +83% shield), and the UI tooltip was patched to properly display a buff (+XX%) instead of a negative penalty.
- [Bugfixed] **Weapon Multi-Projectile Math Fix:** Fixed broken multi-projectile engine math on the Pulse Laser, Cyclone, and Avalanche that was causing unintended DPS doubling.
- [Bugfixed] **Multiplayer RNG Synchronization:** Completely rebuilt the RNG physics calculations inside all 7 new subsystems and anomaly generators. By replacing `math.random` with the deterministic Avorion `Random(Seed(seed))` architecture, physics and stats no longer permanently desync between Multiplayer clients.
- [Bugfixed] **Complete Script QA Hardening:** Eradicated dangerous direct dereference assumptions. Fixed severe silent crashes in `entity/init.lua` and `Tech.lua` where evaluating an unowned entity triggered `attempt to index a nil value` server exceptions. The mod is now 100% crash-safe in heavy multiplayer environments.
- [Bugfixed] **Player Alliance Compatibility:** Hardened script owner resolution logic to explicitly query `player.allianceIndex`. Active subsystem user interfaces will no longer crash or fail to render when players pilot an Alliance-owned vessel.
- [Bugfixed] **Combat Injection Handler:** Legendary Plasma and AntiMatter weapons now correctly tag targets with `[Burn]` and `[Melt]`, applying localized tick damage.
- [Bugfixed] **Set Bonus UI & Logic:** Eradicated vestigial local variables (`lastCheckTime`, `activeModifiers`) leftover from deprecated polling loops. Fixed a severe vanilla engine enum capitalization typo (`WeaponType.PointDefenseChainGun`) that was causing Point Defense Chainguns to fail to register for the Point Defense Doctrine. Standardized the initialization of `ShipSystem()` to match vanilla syntax.
- [Bugfixed] **SoundLib Linux Crash Fixes:** Resolved widespread weapon audio crashes on Linux-based dedicated servers by batch-renaming all physical audio `.wav` files and explicitly downcasing all string references inside the Lua weaponsound scripts.
- [Bugfixed] **Invalid Stat API Sweeps:** Scanned and purged the codebase of invalid vanilla API enums (e.g. `StatsBonuses.Damage`, `StatsBonuses.ShieldCapacity`) and replaced them with functional Vanilla Engine equivalents to eliminate silent math failures.
- [Bugfixed] **Memory Leak Patch:** Fixed a critical bug in `starfall_setbonuses.lua` and `XperimentalHypergenerator.lua` where unpurged volatile keys caused infinite stat stacking upon server restart. Replaced with native `Entity():removeScriptBonuses()` for flawless buff cleanup.
- [Bugfixed] **Phantom Property Patch:** Removed a dangerous write operation to `entity.damageMultiplier` in `starfall_setbonuses.lua` (which is a read-only phantom property that crashes the internal Lua VM) and correctly redirected the buff to `StatsBonuses.FireRate`.
- [Bugfixed] **Generator Math Fixes:** Fixed a game-breaking `ColorHSV` parameter error in `weapongenerator.lua` that was crashing vanilla generation math, and removed an invalid `return TurretIngredients` in `turretingredients.lua` to prevent fatal loading errors.
- [Bugfixed] **AI Ship Sync Fixes:** Resolved an issue in `starfall_setbonuses.lua` where `invokeClientFunction` would crash the server when processing AI/NPC ships by swapping to `broadcastInvokeClientFunction` and implementing strict `Player().craftIndex` UI gating.
- [Bugfixed] **UI Bloom Glitch Patch:** Fixed a severe typo in `ColorLib.lua` where the fallback UI color value was mistakenly set to 100 (10000% brightness), causing massive unpredictable UI bloom and glow artifacts when active systems were rendered.
- [Bugfixed] **Redundant Vault Injections:** Scrubbed obsolete Vault UI code (`cosmicconfig`, `cosmiccodex`) that was illegally injected inside the Starfall mod namespace, avoiding UI overlap bugs.
- [Bugfixed] **In-Game Wiki Loading Crash:** Fixed missing global definitions (`rangeType`, `accuracyType`, etc.) in `infoWeapons.lua` that prevented the weapons wiki from loading correctly and crashed the UI.
- [Bugfixed] **Multiplayer Network Synchronization:** Fixed a silent networking bug where UI buttons for the Overpowered Core would not respond on Dedicated Servers because the server-side functions were missing `callable()` declarations.
